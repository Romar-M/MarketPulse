# MarketPulse — приложение для анализа цен фьючерса ETHUSDT

_Определение собственных движений цены ETH путём исключения влияния BTCUSDT. Python 3.11 + PostgreSQL + Docker._

**Приложение для анализа цен фьючерса ETHUSDT**  
Определяет собственные движения цены ETH, исключая влияние BTCUSDT, через коэффициент β. Работает в реальном времени: WebSocket Binance → анализатор → алерты (консоль/Telegram) + FastAPI + Streamlit-дашборд.

## 🎯 Описание задачи

### Часть 1. Методика анализа

Определить **собственные движения** цены фьючерса ETHUSDT, исключив из них движения, вызванные влиянием цены BTCUSDT. Описать выбранную методику, подобранные параметры и обоснование.

### Часть 2. Программа для анализа цен в реальном времени

- Считывает данные в реальном времени с минимальной задержкой (WebSocket Binance)
- Определяет собственные движения цены ETH
- При изменении собственной цены на **1% за последние 60 минут** формирует алерт
- Работает постоянно, автоматически переподключаясь при обрыве WebSocket

## 🔬 Методика анализа

### 1. Постановка задачи

Цена ETHUSDT частично обусловлена движением BTCUSDT (корреляция крипторынка). Требуется **исключить влияние BTC** и выявить **собственные движения ETH**, вызванные уникальными факторами (новости сети Ethereum, DeFi-активность, активность китов и т.д.).

### 2. Алгоритм (реализованный в `src/analyzer.py`)

**Шаг 1. Сбор данных** — каждую минуту через WebSocket Binance получаем цены закрытия свечей:
- `P_eth(t)` — цена ETHUSDT в минуту `t`
- `P_btc(t)` — цена BTCUSDT в минуту `t`

**Шаг 2. Расчёт коэффициента β** за окно `W = 60` минут по доходностям:
```
R_eth(i) = (P_eth(i) - P_eth(i-1)) / P_eth(i-1)
R_btc(i) = (P_btc(i) - P_btc(i-1)) / P_btc(i-1)

β = Cov(R_eth, R_btc) / Var(R_btc)
```

**Шаг 3. Собственное движение ETH за окно** (в коде — `check_alert`):
```
Δ_eth = P_eth(t) - P_eth(t-W)
Δ_btc = P_btc(t) - P_btc(t-W)
own_move = Δ_eth - β × Δ_btc
pct_change = own_move / P_eth(t-W)
```

**Шаг 4. Проверка алерта** — если `|pct_change| ≥ threshold (1%)` и прошло не менее 5 минут с прошлого алерта (антиспам) — формируется сообщение и сохраняется в БД (+ отправка в Telegram при наличии токена).

### 3. Обоснование параметров

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| **Окно W** | 60 минут | Достаточно для расчёта ковариации (60 точек). Меньшее окно (30 мин) даёт высокую погрешность β. |
| **Порог** | 1% | Движения <1% за час — рыночный шум. 1% фильтрует большинство ложных срабатываний. |
| **Прогрев буфера** | 30 свечей минимум | Алерт не сработает, пока не накоплено минимум 30 точек каждого инструмента (из БД при старте + поступление в реальном времени). |
| **Период проверки** | 30 сек (`alert_check_interval`) | Алерты проверяются по расписанию фоновой задачей, а не на каждый тик. |
| **Антиспам** | 5 минут | Предотвращает лавину сообщений при волатильности. |
| **Реконнект WS** | 10 попыток, пауза 5 сек, ping 20 сек | Устойчивость к обрывам сети и «тихим» периодам. |
| **Защита от деления на ноль** | `Var == 0` → β не пересчитывается | Если BTC не двигался — влияние BTC равно нулю. |

### 4. Альтернативные подходы (и почему не выбраны)

| Метод | Причина отклонения |
|-------|-------------------|
| Простая разница `ETH - BTC` | Не учитывает разную волатильность. ETH обычно волатильнее BTC. |
| Коинтеграция (Engle-Granger) | Сложнее в реализации, требует больше данных. β-коррекция даёт аналогичный результат при меньших затратах. |
| MA-фильтрация (скользящее среднее) | Не разделяет ETH и BTC, а просто сглаживает. |

## 🚀 Установка и запуск

### Требования

- Docker и Docker Compose
- Python 3.11 (для локального запуска без Docker)

### 1. Клонирование репозитория

```bash
git clone https://github.com/Romar-M/MarketPulse.git
cd MarketPulse
```

### 2. Настройка переменных окружения

```bash
cp .env.example .env
# Отредактируйте .env при необходимости
```

Основные переменные: `DB_USER`, `DB_PASS`, `DB_NAME`, `DB_HOST`, `THRESHOLD` (0.01), `WINDOW_MINUTES` (60), `ALERT_CHECK_INTERVAL` (30), `TELEGRAM_TOKEN`, `TELEGRAM_CHAT_ID`.

### 3. Запуск через Docker Compose

```bash
docker compose up -d --build
```

Поднимаются 4 сервиса:

| Сервис | Назначение | Порт |
|--------|-----------|------|
| `db` | PostgreSQL | 5432 |
| `app` | FastAPI + WebSocket-клиент + анализатор | 8000 |
| `scheduler` | Фоновая проверка алертов | — |
| `dashboard` | Streamlit-дашборд | 8501 |

### 4. Локальный запуск (без Docker)

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
python -m src.main
```

