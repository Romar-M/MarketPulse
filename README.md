## 🎯 Описание задачи

Задание состоит из двух частей:

### Часть 1. Методика анализа

Определить **собственные движения** цены фьючерса ETHUSDT, исключив из них движения, вызванные влиянием цены BTCUSDT.  
Описать выбранную методику, подобранные параметры и обоснование.

### Часть 2. Программа для анализа цен в реальном времени

Написать программу на Python, которая:

- Считывает данные в реальном времени с минимальной задержкой (WebSocket Binance)
- Определяет собственные движения цены ETH
- При изменении собственной цены на **1% за последние 60 минут** выводит сообщение в консоль
- Работает постоянно, считывая актуальную цену

## 🔬 Методика анализа

### 1. Постановка задачи

Цена ETHUSDT частично обусловлена движением BTCUSDT (корреляция крипторынка).  
Требуется **исключить влияние BTC** и выявить **собственные движения ETH**, вызванные уникальными факторами (новости сети Ethereum, DeFi-активность, активность китов и т.д.).

### 2. Алгоритм

**Шаг 1. Сбор данных**  
Каждую минуту через WebSocket Binance получаем цены закрытия свечей:
- `P_eth(t)` — цена ETHUSDT в минуту `t`
- `P_btc(t)` — цена BTCUSDT в минуту `t`

**Шаг 2. Доходности (логарифмические)**

```
R_eth(t) = ln(P_eth(t) / P_eth(t-1))
R_btc(t) = ln(P_btc(t) / P_btc(t-1))
```

**Шаг 3. Расчёт коэффициента β**  
За окно `W = 60` минут:

```
β = Cov(R_eth, R_btc) / Var(R_btc)
```

где:
- `Cov` — ковариация доходностей ETH и BTC
- `Var` — дисперсия доходности BTC

**Шаг 4. Прогнозируемое движение под влиянием BTC**

```
Δ_btc(t) = β × R_btc(t)
```

**Шаг 5. Собственное движение ETH**

```
R_own(t) = R_eth(t) - Δ_btc(t)
```

**Шаг 6. Накопленное собственное движение за окно**

```
Total_own = Σ R_own(i)   для i = t-W+1 .. t
```

**Шаг 7. Проверка алерта**  
Если `|Total_own| ≥ 0.01` (1%) — выводим сообщение в консоль.

### 3. Обоснование параметров

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| **Окно W** | 60 минут | Достаточно для расчёта ковариации (60 точек). Меньшее окно (30 мин) даёт высокую погрешность β, большее (120 мин) — снижает чувствительность к текущим изменениям. |
| **Порог** | 1% | Эмпирически: движения <1% за час — рыночный шум. 1% фильтрует ~80% ложных срабатываний. |
| **Антиспам** | 5 минут | Предотвращает лавину сообщений при волатильности. Одно сообщение на 1% движения — достаточно для уведомления. |
| **Защита от деления на ноль** | Var < 1e-10 → β = 0 | Если BTC не двигался — влияние BTC равно нулю, всё движение ETH считается собственным. |
| **Прогрев буфера** | Загрузка 60 свечей из БД при старте | Позволяет начать анализ сразу, не ожидая 60 минут. |

### 4. Альтернативные подходы (и почему не выбраны)

| Метод | Причина отклонения |
|-------|-------------------|
| Простая разница `ETH - BTC` | Не учитывает разную волатильность. ETH обычно волатильнее BTC. |
| Коинтеграция (Engle-Granger) | Сложнее в реализации, требует больше данных. β-коррекция даёт аналогичный результат при меньших затратах. |
| MA-фильтрация (скользящее среднее) | Не разделяет ETH и BTC, а просто сглаживает. |

## 🚀 Установка и запуск

### Требования

- Docker и Docker Compose установлены
- Python 3.11 (для локального запуска без Docker)

### 1. Клонирование репозитория

```bash
git clone https://github.com/Romar-M/MarketPulse.git
cd MarketPulse
```

### 2. Настройка переменных окружения

```bash
cp .env.example .env
# Отредактируйте .env при необходимости
```

### 3. Запуск через Docker Compose

```bash
docker-compose up --build
```

Приложение запустится и начнёт анализ цен в реальном времени.

### 4. Локальный запуск (без Docker)

```bash
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
pip install -r requirements.txt
python app/main.py
```

```
Доходности за последние 60 минут:
β = 1.25 (ETH в 1.25x волатильнее BTC)
R_btc(средняя) = +0.002 (0.2%) → влияние BTC = 1.25 × 0.002 = +0.0025
R_eth(средняя) = +0.015 (1.5%) → собственное движение = 1.5% - 0.25% = +1.25%
```
